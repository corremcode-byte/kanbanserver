# Deployment Guide

## Quick Setup

### 1. Install and Setup
```bash
cd server
npm install
cp env.example .env
# Edit .env with your configuration
```

### 2. Required Environment Variables
```env
MONGODB_URI=mongodb://localhost:27017/asana-clone
FIREBASE_PROJECT_ID=your-project-id
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
FIREBASE_CLIENT_EMAIL=firebase-adminsdk-xxx@your-project.iam.gserviceaccount.com
JWT_SECRET=your-secret-key
ALLOWED_ORIGINS=http://localhost:3000
```

### 3. Start Server
```bash
# Development
npm run dev

# Production
npm run build
npm start
```

## Frontend Integration

Update your frontend `.env.local`:
```env
NEXT_PUBLIC_API_URL=http://localhost:4001
```

Your existing frontend code will work immediately with this backend!

## Database Setup

### Option A: Local MongoDB
```bash
# Install MongoDB
brew install mongodb-community  # macOS
# or download from https://www.mongodb.com/try/download/community

# Start MongoDB
brew services start mongodb-community
```

### Option B: MongoDB Atlas
1. Create account at https://cloud.mongodb.com/
2. Create cluster
3. Get connection string
4. Update `MONGODB_URI` in `.env`

## Firebase Setup

1. Go to https://console.firebase.google.com/
2. Create/select project
3. Enable Authentication
4. Go to Project Settings > Service Accounts
5. Generate private key
6. Copy credentials to `.env`

## Health Check

Test your setup:
```bash
curl http://localhost:4001/health
```

Should return:
```json
{
  "status": "healthy",
  "timestamp": "2024-01-01T00:00:00.000Z",
  "uptime": 123.456

```

## API Endpoints

All endpoints match your frontend exactly:
- `GET /api/tasks` - All user tasks
- `POST /api/tasks/:projectId` - Create task
- `GET /api/projects` - All projects
- `POST /api/projects` - Create project
- `GET /api/teams` - All teams
- `POST /api/teams` - Create team
- `GET /api/notifications` - All notifications

## WebSocket Events

Real-time events your frontend already listens for:
- `task:created`, `task:updated`, `task:deleted`
- `project:created`, `project:updated`
- `team:created`, `team:updated`
- `notification:new`, `notification:read`

## Troubleshooting

### Connection Issues
1. Check MongoDB is running
2. Verify Firebase credentials
3. Check CORS origins match frontend URL

### Frontend Connection
Your existing frontend should connect automatically if:
- Backend runs on port 4001
- `NEXT_PUBLIC_API_URL=http://localhost:4001` is set

### Authentication
Firebase tokens from frontend are automatically validated by backend.

## Production Deployment

### Render (Recommended)

#### Prerequisites
1. **MongoDB Atlas** (Free Tier Available)
   - Sign up at https://cloud.mongodb.com/
   - Create a cluster
   - Get your connection string (should look like: `mongodb+srv://username:password@cluster.mongodb.net/kanban`)
   - Whitelist all IPs (0.0.0.0/0) for Render access

2. **Firebase Service Account**
   - Get credentials from Firebase Console
   - Have your FIREBASE_PROJECT_ID, FIREBASE_PRIVATE_KEY, and FIREBASE_CLIENT_EMAIL ready

#### Quick Deploy with render.yaml
This repo includes a `render.yaml` file for one-click deployment:

1. **Push to GitHub**
   ```bash
   git add .
   git commit -m "Prepare for Render deployment"
   git push origin main
   ```

2. **Create Render Account**
   - Go to https://render.com/
   - Sign up/login with GitHub

3. **Deploy from Blueprint**
   - Click "New +" > "Blueprint"
   - Connect your GitHub repository
   - Render will detect `render.yaml` automatically
   - Click "Apply"

4. **Configure Environment Variables**
   In the Render dashboard, go to your service and set these environment variables:

   ```
   MONGODB_URI=mongodb+srv://username:password@cluster.mongodb.net/kanban
   FIREBASE_PROJECT_ID=your-firebase-project-id
   FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nYour-Key-Here\n-----END PRIVATE KEY-----\n"
   FIREBASE_CLIENT_EMAIL=firebase-adminsdk-xxx@project.iam.gserviceaccount.com
   ALLOWED_ORIGINS=https://your-nextjs-app.vercel.app,https://your-custom-domain.com
   ```

   **Important Notes:**
   - `JWT_SECRET` is auto-generated by Render
   - `FIREBASE_PRIVATE_KEY` must include `\n` for newlines
   - `ALLOWED_ORIGINS` should be comma-separated list of your frontend URLs
   - `PORT` and `NODE_ENV` are set automatically in render.yaml

5. **Deploy**
   - Render will automatically build and deploy
   - Wait for deployment to complete (2-5 minutes)
   - Your service URL will be: `https://kanban-server.onrender.com`

#### Manual Deploy (Alternative)

If you prefer not to use render.yaml:

1. **Create New Web Service**
   - Dashboard > "New +" > "Web Service"
   - Connect GitHub repository
   - Configure:
     - **Name**: kanban-server
     - **Runtime**: Node
     - **Branch**: main
     - **Build Command**: `npm install && npm run build`
     - **Start Command**: `npm start`
     - **Instance Type**: Free (or paid for better performance)

2. **Add Environment Variables** (same as above)

3. **Advanced Settings**
   - **Health Check Path**: `/health`
   - **Auto-Deploy**: Yes (recommended)

#### Post-Deployment

1. **Test Your Deployment**
   ```bash
   curl https://your-app.onrender.com/health
   ```

   Expected response:
   ```json
   {
     "status": "healthy",
     "timestamp": "2024-01-01T00:00:00.000Z"
   }
   ```

2. **Update Your Next.js Frontend**

   In your Next.js project's `.env.local` or Vercel environment variables:
   ```env
   NEXT_PUBLIC_API_URL=https://your-app.onrender.com
   ```

3. **Configure CORS**

   Make sure `ALLOWED_ORIGINS` in Render includes your frontend URL:
   ```
   ALLOWED_ORIGINS=https://your-nextjs.vercel.app,https://www.yourdomain.com
   ```

#### WebSocket Support

Render fully supports WebSocket connections, so your Socket.IO real-time features will work perfectly. No additional configuration needed.

#### Important Considerations

**Free Tier Limitations:**
- Service spins down after 15 minutes of inactivity
- First request after spin-down takes 30-60 seconds to wake up
- 750 hours/month free (shared across services)

**Recommendations for Production:**
- Use Starter ($7/month) or higher for always-on service
- Enable auto-scaling for high traffic
- Set up monitoring and alerts

**File Uploads:**
- Render's filesystem is ephemeral (resets on deploy)
- For file uploads (if using multer), integrate cloud storage:
  - AWS S3
  - Cloudinary
  - Google Cloud Storage

**Database Backups:**
- MongoDB Atlas handles backups automatically
- Consider setting up additional backup strategy for production

#### Troubleshooting

**Build Fails:**
- Check build logs in Render dashboard
- Ensure `package.json` has correct scripts
- Verify Node version compatibility

**Service Won't Start:**
- Check logs for errors
- Verify all required environment variables are set
- Test MongoDB connection string locally first

**CORS Errors:**
- Verify `ALLOWED_ORIGINS` includes your frontend domain
- Check for trailing slashes in URLs
- Ensure protocol matches (https vs http)

**WebSocket Connection Issues:**
- Render supports WebSockets by default
- Check that frontend is connecting to correct URL
- Verify no proxy/firewall blocking WebSocket connections

#### Monitoring

Render provides:
- Real-time logs
- Metrics dashboard
- Email alerts for service issues

Access logs:
```bash
# In Render dashboard: Services > Your Service > Logs
```
